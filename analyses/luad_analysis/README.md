# LUAD stage analysis (paper Figure 5, Supplementary Figures 3–8)

**Question.** In TCGA lung adenocarcinoma, does expression of the top-1% CORAL candidate isoforms of IGF2BP1,
IGF2BP3 or LIN28B vary with AJCC pathological stage in the tumors that express that RBP? Is the association
stronger than for comparable transcripts that CORAL did not select?

**Follow-ups (s5, s6, s8).** For the IGF2BP1 association, they ask whether it is carried by N or T, whether it
requires IGF2BP1, and whether tumor purity explains it.

The checkpoint is the paper's final model (Zenodo weights v3), named in `config.json`. Locally it sits in
`checkpoints/coraldegree50-fulldataset-epoch-9/`; `scripts/download_weights.sh` puts the same files in
`checkpoints/coral-epoch-9/`, so point `"checkpoint"` there after a fresh download. Predictions are checked
against the checkpoint's SHA-256, not its name.

## Layout

```
analyses/luad_analysis/
├── config.json      every parameter, and the SHA-256 of every input
├── scripts/
│   ├── common.py    paths, config, IO, statistics and the matched random panels shared by every step
│   ├── plotting.py  supplementary-figure style and the SVG + JPEG writer used for every figure
│   ├── inputs/      build data/luad/ and run CORAL on it (once)
│   └── steps/       s1–s8 and figure_main: the analysis
├── tables/          every table the steps write
├── figures/         main/ and Supplementary/, each as svg/ and jpg/
└── tests/           synthetic-data tests of common.py
```

`tables/` holds both the result tables and the per-patient scores, rankings and null distributions that later
steps read. Only the result tables are versioned. The other tables (about 14 MB) and the figures are regenerated by
the steps.

## Inputs (`scripts/inputs/`)

Run each once, from the repository root, as `python analyses/luad_analysis/scripts/inputs/<script>`
(`bash` for `run_inference.sh`). Only `run_inference.sh` depends on the checkpoint.

| Script | Writes |
| --- | --- |
| `download_sources.py` | `data/luad/luad_sources/`: GENCODE v23 GTF and FASTA, the 59 Xena normal samples, the three UniProt proteins. Every file is hash-checked. |
| `download_purity.py` | `data/luad/luad_sources/ncomms9971-s2.xlsx`: consensus purity estimates (Aran et al. 2015, Supplementary Data 1), hash-checked. |
| `prepare_inputs.py` | `data/luad/luad_*`: expression, samples, transcripts, inference sequences and proteins. Logs the per-RBP eligibility counts. |
| `run_inference.sh` | `data/luad/luad_predictions/<checkpoint-name>/`: CORAL scores of every inference RNA against the three RBPs. Needs GPUs. |

Two sources must be placed in `data/luad/` by hand:

- `LUAD_isoforms.tsv`: UCSC Xena Toil RSEM isoform TPM for the 513 primary tumors. `download_sources.py` checks
  its SHA-256, sample count and transcript count.
- `luad_samples_GDC_metadata.txt`: GDC clinical records per sample (Data Release 46.0), with pathological AJCC
  stage and TNM. Its SHA-256 is pinned in `config.json`.

`prepare_inputs.py` scores more RNAs than the analysis uses: its inference set is every ACGT sequence of
≤ 6,000 nt with TPM ≥ 0.5 in ≥ 10% of the positive tumors of any RBP. The s1 universes (TPM ≥ 1 in ≥ 50%) are
a subset, so the predictions cover them.

## Steps (`scripts/steps/`)

| Script | Question | Outputs |
| --- | --- | --- |
| `s1_cohorts.py` | Which tumors express each RBP (protein-coding TPM > 1), and which transcripts are expressed alongside it (TPM ≥ 1 in ≥ 50% of positive tumors, ACGT, ≤ 6,000 nt)? | `tables/cohorts.tsv`, `tables/universes.parquet`, `tables/cohort_summary.tsv` |
| `s2_panels.py` | Which transcripts does CORAL rank in the top 1% per RBP? How do they differ from their universe in length, GC content and expression? | `tables/rankings.parquet`, `tables/panel_summary.tsv` |
| `s3_overlap.py` | Do the panels overlap, and is CORAL's ranking protein-specific? | `tables/overlap.tsv`, `tables/margin_correlation.tsv` |
| `s4_stage.py` | Is the panel score, log2(median TPM + 1), associated with stage I–IV? Uses Spearman, a 99,999-permutation P, a 2,000-bootstrap CI and BH across the 3 RBPs, plus competitive P against 9,999 random panels matched on expression × length, with and without GC matching | `tables/stage_association.tsv`, `tables/patient_scores.tsv`, `tables/null_distribution.parquet`, Supplementary Figures 3–4 |
| `s5_tnm.py` | Is the IGF2BP1 gradient carried by pathological N, T, or both? Univariate and partial (N \| T, T \| N) effects; BH over 4 | `tables/tnm_association.tsv`, `tables/tnm_patients.tsv`, Supplementary Figure 7 |
| `s6_igf2bp1_dependence.py` | Does the gradient require IGF2BP1? Tests three things (BH over 3): stage in IGF2BP1-negative tumors; coupling of the panel to IGF2BP1 level across all tumors; stage \| IGF2BP1 level in positives | `tables/dependence.tsv`, `tables/dependence_stage_counts.tsv`, `tables/dependence_scores.tsv`, `tables/dependence_null.parquet`, Supplementary Figures 5–6 |
| `s8_composition.py` | Does tumor purity (CPE) explain the gradient or its excess over random panels? | `tables/composition.tsv`, `tables/composition_patients.tsv`, Supplementary Figure 8 |
| `figure_main.py` | Figure 5 a–d: panel overlap, IGF2BP1 stage ρ against its random panels, median panel score by stage in IGF2BP1-positive and -negative tumors, N vs T. Display only | `figures/main/{svg,jpg}/` (each panel and the assembled `figure_main`) |

There is no s7: the step numbers follow the analysis plan, and its seed streams (`[seed, <step>, k]`) are keyed
to them.

## Design rules

- Every parameter is in `config.json`. Every input from `data/luad/` is SHA-256-pinned there.
- Panels are fixed in s2 from sequence-based scores alone, before any clinical file is read. Clinical data are read
  only from s4 on.
- CORAL predictions are read from `data/luad/luad_predictions/<checkpoint-name>/` after the checkpoint hash is
  checked.
- Fixed seeds: reruns reproduce every table.
- **One null for everything.** s5, s6 and s8 rebuild s4's exact 9,999 matched random panels (`common.null_panels`).
  Before using them, they check that the rebuilt panels reproduce s4's saved scores and null correlations. Every
  follow-up statistic carries a competitive P, so each result can be read as a broad gradient or as CORAL-specific.
- **Outcome for s8.** It was chosen after s5 by a rule written down beforehand: N if the N | T CI excludes 0
  and the T | N CI includes 0, otherwise stage. s5 gave N | T [−0.39, 0.01] and T | N [−0.48, −0.07], so the outcome
  is **stage** (`config.json → followup.outcome`). N is reported as a descriptive row. s8 refuses to run while the
  outcome is unset.

## Running

From the repository root, in the `coral` environment (no extra packages), after the inputs:

```bash
for s in s1_cohorts s2_panels s3_overlap s4_stage s5_tnm s6_igf2bp1_dependence s8_composition figure_main; do
  conda run --no-capture-output -n coral python analyses/luad_analysis/scripts/steps/$s.py
done
conda run -n coral python -m unittest discover \
  -s analyses/luad_analysis/tests -t analyses/luad_analysis/tests
```

The whole run takes about 5 min on CPU.

s4, s5, s6 and s8 accept `--figures-only`, which redraws figures from the saved tables. `figure_main.py` only
reads saved tables.
